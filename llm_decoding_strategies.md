# LLM Decoding Strategies — Complete Guide

Decoding strategies determine **how an LLM converts probability distributions into actual text output**.
Every word/token generated by an LLM is controlled by a decoding strategy.

---

## 🧠 How Decoding Works (Quick Overview)

```
Input Prompt
     ↓
LLM computes probability for EVERY possible next token
     ↓
[the=0.4, a=0.2, my=0.15, her=0.1, ...]
     ↓
Decoding Strategy picks which token to use
     ↓
Token added to output → repeat until done ✅
```

---

## 📦 Two Main Categories

| Category | What it means | Examples |
|---|---|---|
| **Deterministic** | Same input = same output every time | Greedy, Beam Search |
| **Stochastic** | Same input = different output each time | Sampling, Top-K, Top-P |

---

## 🔵 PART 1: Basic / Foundational Decoding Strategies

---

### 1. 🟢 Greedy Search

**The simplest method** — always picks the single highest probability token at each step.

```
Probabilities:  [the=0.6, a=0.2, my=0.1, ...]
Greedy picks →   "the"  ✅ (always highest)
```

| Pros | Cons |
|---|---|
| Very fast | Repetitive outputs |
| Deterministic | Misses better overall sequences |
| Low compute | Poor for creative tasks |

**Best for:** Simple factual responses, when speed matters most

---

### 2. 🔵 Beam Search

**Keeps track of multiple sequences** (beams) simultaneously and picks the best overall.

```
Beam Width = 3 → tracks 3 possible sequences at once

Step 1:  "The" | "A" | "My"
Step 2:  "The cat" | "A dog" | "My horse"
Step 3:  "The cat sat" | "A dog ran" | "My horse fell"
→ Picks overall best scoring sequence
```

| Pros | Cons |
|---|---|
| Higher quality output | Slower than greedy |
| Finds better sequences | Can still be repetitive |
| Good for translation | Less creative/diverse |

**Best for:** Machine translation, summarization, structured tasks

---

### 3. 🟡 Diverse Beam Search

An **extension of Beam Search** that forces beams to explore different paths, producing more varied outputs.

```
Normal Beam Search → 3 very similar sequences
Diverse Beam Search → 3 very different sequences
```

**Best for:** When you need multiple distinct answers/suggestions

---

### 4. 🟠 Multinomial Sampling

**Randomly selects a token** based on its probability — higher probability tokens are more likely but not guaranteed.

```
Probabilities: [the=0.6, a=0.2, my=0.1, her=0.1]
Could pick →  "the" (60% chance) OR "a" (20%) OR "my" (10%)
```

| Pros | Cons |
|---|---|
| More variety | Can produce incoherent text |
| Less repetitive | Unpredictable |
| Creative outputs | Random low-prob tokens possible |

**Best for:** Creative writing, brainstorming

---

## 🟣 PART 2: Sampling Refinements

---

### 5. 🌡️ Temperature Sampling

**Controls how "random" or "focused" the sampling is** by scaling the probability distribution.

```
Low Temperature (0.1) → Very focused, predictable
  [the=0.95, a=0.04, my=0.01]

High Temperature (1.5) → Very random, creative
  [the=0.35, a=0.25, my=0.20, her=0.20]
```

| Temperature | Effect | Use Case |
|---|---|---|
| 0.0 | Same as Greedy | Facts, code |
| 0.3–0.7 | Balanced | General chat |
| 0.8–1.0 | Creative | Stories, ideas |
| >1.0 | Very random | Experimental |

---

### 6. 🔝 Top-K Sampling

**Limits random selection to only the top K most probable tokens** — rest are set to zero.

```
Full vocab: [the=0.4, a=0.2, my=0.15, her=0.1, cat=0.08, ...]
Top-K (K=3): [the=0.4, a=0.2, my=0.15] → sample from only these 3
```

| Pros | Cons |
|---|---|
| Avoids nonsense tokens | K is fixed regardless of context |
| More coherent | May include bad tokens if K too large |

---

### 7. 🔵 Top-P (Nucleus) Sampling

**Dynamically selects tokens** whose cumulative probability reaches threshold P — adapts to context.

```
P = 0.9 → Keep adding tokens until cumulative prob hits 90%

Sharp distribution:  picks fewer tokens (top 2–3 cover 90%)
Flat distribution:   picks more tokens (need top 20 to cover 90%)
```

| Pros | Cons |
|---|---|
| Adapts to context | P value needs tuning |
| Better than fixed Top-K | Slightly complex |
| Industry standard | Can still be inconsistent |

**Most widely used sampling method in production LLMs**

---

### 8. 🔻 Min-P Sampling

**Sets a minimum probability threshold** relative to the highest probability token. Tokens below this relative threshold are cut off.

```
Top token prob = 0.6, Min-P = 0.1
Min threshold = 0.6 × 0.1 = 0.06
Only tokens with prob > 0.06 are kept
```

**Newer method (2024)** — often outperforms Top-P for creative tasks

---

### 9. 📊 Locally Typical Sampling

**Selects tokens that are "typical" for the local context** — neither too surprising nor too predictable — balancing diversity and coherence.

Uses statistical typicality: tokens should have information content close to the average expected for that context.

**Best for:** Long-form generation where coherence over time matters

---

### 10. 🔢 Eta (η) Sampling

**An improvement over Top-P** that introduces a dynamic threshold based on the probability distribution's entropy. Adapts more intelligently than fixed P values.

---

## 🔴 PART 3: Advanced & Anti-Hallucination Decoding

---

### 11. ⚡ Contrastive Decoding

**Compares outputs of a large model vs. a small model** — takes the difference to amplify important tokens.

```
Large Model (OPT-13B) probability - Small Model (OPT-125M) probability
= Amplified signal for factually important tokens
```

**Key idea:** Large models know MORE than small models — the difference highlights what large models uniquely know.

**Best for:** Reducing hallucinations, improving factuality

---

### 12. 🔬 DoLa (Decoding by Contrasting Layers)

**Contrasts logits from different layers** within the SAME model instead of two separate models.

```
Higher layers → More factual knowledge
Lower layers  → More surface-level patterns

DoLa = Higher Layer logits - Lower Layer logits
     = More factual output
```

| Feature | DoLa |
|---|---|
| Developed by | MIT + Microsoft |
| Goal | Reduce hallucinations |
| No extra model needed | ✅ Uses one model |
| Works on | LLaMA family and others |

**Best for:** Factual Q&A, reducing hallucinations without extra models

---

### 13. 🔎 Contrastive Search

**Combines probability with a diversity penalty** to avoid repetition while maintaining coherence.

```
Score = α × Model Probability - (1-α) × Similarity to past tokens
```

Penalizes tokens that are too similar to recently generated tokens.

**Best for:** Long-form generation, avoiding repetitive loops

---

### 14. 🚀 Speculative Decoding

**Uses a small draft model to generate multiple tokens**, then verifies them all at once with the large model.

```
Small Model (fast):  "The cat sat on the" → generates 5 tokens quickly
Large Model (slow):  verifies all 5 tokens in ONE forward pass
→ If accepted: saves 4 forward passes!
→ If rejected: falls back to large model token
```

| Feature | Detail |
|---|---|
| Speed gain | 2–3× faster inference |
| Output quality | Identical to original model |
| Cost | Need a small draft model |
| Used in | Production LLM APIs |

**Best for:** Speeding up inference without quality loss

---

### 15. 🔭 Lookahead Decoding

**Predicts multiple future tokens in parallel** using the large model itself, breaking sequential dependency.

```
Normal:     Token1 → Token2 → Token3 → Token4 (sequential)
Lookahead:  Token1 → [Token2, Token3, Token4] (parallel prediction)
```

Achieves speedups without needing a separate draft model.

---

### 16. 📚 REST (Retrieval-Based Speculative Decoding)

**Fetches candidate tokens from a pre-built datastore** using the current context, then verifies with the LLM.

```
Context → Search datastore → Retrieve matching token sequences
        → LLM verifies → Accept or reject
```

**Best for:** Domain-specific generation where relevant text exists in a corpus

---

### 17. 🧩 Constrained Decoding

**Forces the output to follow specific rules**, formats, or constraints.

**Types of constraints:**
- Must include certain phrases
- Must follow JSON/XML format
- Must avoid banned words
- Must follow a grammar

```
Constraint: "Output must be valid JSON"
→ Decoding ONLY allows tokens that keep the output valid JSON at every step
```

**Best for:** Structured output (JSON, code, forms), safety filtering

---

### 18. 🖼️ Multimodal Decoding

**Generates output in one modality based on input from another** (text, image, audio, video).

```
Image → LLM → Text description
Audio → LLM → Text transcript
Text  → LLM → Image description for generation
```

**Used in:** GPT-4V, Claude Vision, Gemini, LLaVA

---

### 19. 🧠 Guided Decoding

**Uses the model's own self-evaluation score** at each step to control generation quality.

The model scores its own partial outputs and uses this as a quality signal to guide which tokens to keep.

**Best for:** Multi-step reasoning, math problem solving

---

### 20. 🔀 Mixture of Experts (MoE) Decoding

**Dynamically selects which "expert" sub-networks** to use for each token generation step.

```
Token generation step:
→ Router selects most relevant experts (e.g., 2 of 8 experts)
→ Only those experts compute the next token
→ More efficient, higher quality
```

**Used in:** Mixtral, GPT-4 (reportedly), DeepSeek

---

### 21. 🎓 Distillation-Driven Decoding

**Leverages knowledge distillation** to optimize the decoding phase — a smaller student model decodes tokens guided by a larger teacher model's distribution.

---

### 22. 🌊 Soft Decoding (Latent / Continuous Decoding)

**Skips discrete token selection entirely** — passes continuous vector representations between steps instead.

```
Normal (Hard) Decoding:   hidden state → pick token → embed token → next step
Soft Decoding:            hidden state ─────────────────────────→ next step
                          (no discrete token selection in between!)
```

**Types:**
| Name | What it does |
|---|---|
| **Coconut** | Feeds final hidden state directly as next input |
| **CoLaR** | Adds RL training to stabilize latent reasoning |
| **SoftThinking** | Averages embeddings weighted by probability |

**Best for:** Complex reasoning tasks, experimental research

## 🗺️ PART 5: Which Strategy to Use When?

```
What's your goal?
│
├── Need SPEED?
│     └── Greedy Search or Speculative Decoding
│
├── Need ACCURACY / FACTS?
│     └── Beam Search, DoLa, Contrastive Decoding
│
├── Need CREATIVITY?
│     └── Temperature + Top-P or Min-P Sampling
│
├── Need STRUCTURED OUTPUT (JSON/Code)?
│     └── Constrained Decoding
│
├── Need NO HALLUCINATIONS?
│     └── DoLa, Contrastive Decoding, DeCoRe
│
├── Building MULTIMODAL app?
│     └── Multimodal Decoding
│
└── RESEARCH / REASONING tasks?
      └── Soft Decoding, Guided Decoding
```

## 🌟 Key Takeaway

| Category | Strategies |
|---|---|
| **Basic** | Greedy, Beam Search, Diverse Beam, Multinomial |
| **Sampling** | Temperature, Top-K, Top-P, Min-P, Typical, Eta |
| **Anti-Hallucination** | Contrastive, DoLa, Contrastive Search |
| **Speed** | Speculative, Lookahead, REST |
| **Structured** | Constrained, Guided |
| **Advanced** | MoE, Distillation, Soft/Latent Decoding |
| **Multimodal** | Multimodal Decoding |

> 💡 Most production LLMs combine multiple strategies:
> e.g., **Top-P + Temperature + Repetition Penalty** all applied together!
